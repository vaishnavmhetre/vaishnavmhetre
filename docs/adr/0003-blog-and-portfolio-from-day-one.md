# Portfolio and blog share one Markdown content model from day one

The site starts as a portfolio but is explicitly planned to evolve into a blog; re-architecting the content model later is the expensive option. We commit to **portfolios and posts as first-class content types from the first scaffold**: `content/posts/` + `content/projects/`, tags, RSS, sitemap, and list templates present at day one — even if only one post and three case studies ship initially. A blog with one post also reads better than a site that visibly lacks a blog section.

Rejected alternative: portfolio-only scaffold with the blog bolted on later (cheaper now, costly later; the content tree, taxonomies, and page layouts would need restructuring).
